# 异动分析 Agent 面试复盘材料事实分层重构设计

## 一、修订目标

本次修订以实习期间真实完成的异动分析 Agent 和用户提供的四张真实截图为事实基础，解决现有复盘材料中的项目性质、能力职责、报告结构、分析维度、建设状态和指标口径冲突。

修订不将复盘测算包装为真实线上成果，也不因缺少完整线上数据而删除有价值的产品设计。所有内容按“真实已验证、当前真实痛点、复盘测算/目标值、后续规划”四类表达。

## 二、事实分层规则

### 2.1 真实已验证

可作为真实实习项目经历表述的内容包括：

- 用户提出一次分析需求后，由 AI Agent 理解意图并编排后续能力。
- 通过 `friday-mcp-query` 完成 CIBA 换票和魔数数据查询，获取本期与对比期数据。
- 依据统一万服口径完成指标计算和 7 维度自动拆解。
- 生成图文一体的 HTML 报告，上传 S3 并获取访问链接。
- 通过大象机器人向指定成员或群聊分发报告。
- 已在到餐客服 WBR 等真实场景验证端到端链路。

没有截图、记录或用户明确说明支持的完成情况，不得写成“已上线”“已验收通过”或“已经取得的业务结果”。

### 2.2 当前真实痛点

以下内容统一写为当前问题或待建设能力：

- 语义取数准确性缺少系统化、可量化的评测机制。
- 不同业务数据尚未实现完善的权限隔离。
- 图表、规则、定时任务和消息分发等通用能力尚未完成工程标准化。
- 个人环境跑通的业务场景难以快速部署到体验 Agent。

### 2.3 复盘测算/目标值

缺少真实线上证据的数据可以保留，但必须在字段名、标题或正文邻近位置明确标注为“复盘测算”“目标值”或“示例值”。包括但不限于：

- 50–70 倍效率提升。
- 87.3% 分析准确率。
- 4.2/5.0 用户满意度。
- DAU、WAU、MAU、报告量、用户人数和调研比例。
- token、CDN、消息推送等成本数据。

目标值不得使用“实际达到”“验收通过”“线上结果”等完成态措辞。

### 2.4 后续规划

尚未完成的评测、权限、标准化、部署和 Badcase 能力进入后续规划，并说明解决的问题、建设内容和验收方法。

## 三、统一业务与产品口径

### 3.1 7 个自动拆解维度

所有文件统一使用以下 7 个分析维度：

1. 城市等级。
2. 事件类别。
3. 六级 FAQ。
4. 门店品类（二级/三级）。
5. 进线渠道。
6. 一级战区。
7. 二级战区。

删除“六类 WBR 分析视角”“6+ 维度”等并行框架。二级和三级门店品类属于一个业务维度中的两个层级；一级和二级战区作为两个独立拆解维度。

### 3.2 统一报告结构

HTML 报告和 Markdown 报告共享以下 5 个内容模块：

1. 核心指标：本期/对比期万服、服务量、订单量及同比或环比变化。
2. 综合结论：整体变化方向、主要推高因素、主要压降因素及注意事项。
3. 日度趋势：本期与对比期的日万服趋势及异常日期。
4. 7 维度拆解：逐维度展示主要波动项、变化方向和业务解释。
5. 明细与告警：维度明细、不可用维度、新增/消失项、极端值和口径风险。

不再分别使用“5 个模块”“7 个模块”“6 个 HTML 区域”等不同计数。视觉组件数量不作为报告信息架构的计数口径。

### 3.3 统一能力链路

```text
用户需求
→ AI Agent 意图识别与能力编排
→ friday-mcp-query：CIBA 换票、两期数据查询
→ anomaly_calc：确定性口径、指标、贡献与标签计算
→ experience-anomaly-report：组织 7 维分析结论与 5 模块报告内容
→ s3plus-upload：生成/发布 HTML 报告、上传 S3、返回链接
→ dx-api-tools-bai：大象个人或群聊分发
```

定时任务由 `daxiang-scheduled-message` 按 Cron 配置触发上述完整链路。学城同步能力按证据写为“已跑通能力”或“待完善”，不得直接表述为成熟的标准化平台能力。

### 3.4 模块职责边界

| 模块 | 统一职责 | 不承担的职责 |
|---|---|---|
| AI Agent | 理解意图、解析参数、选择并编排能力、处理异常分支 | 不自行进行数值计算 |
| `friday-mcp-query` | CIBA 换票、数据集查询、本期与对比期数据获取 | 不生成业务结论 |
| `anomaly_calc` | 万服、变化率、服务量变化占比、万服波动贡献和告警标签的确定性计算 | 不自由生成分析文字 |
| `experience-anomaly-report` | 基于结构化计算结果生成 7 维分析和 5 模块报告内容 | 不重新计算或改写数值 |
| `s3plus-upload` | HTML 渲染/发布、S3 上传、返回报告链接 | 不负责异动归因 |
| `dx-api-tools-bai` | 向大象个人或群聊分发报告链接 | 不负责报告生成 |
| `daxiang-scheduled-message` | 定时触发、任务配置和执行记录 | 不承担分析计算 |

## 四、统一指标口径

### 4.1 万服

```text
万服 = 服务量 ÷ 订单量 × 10000
```

### 4.2 服务量变化占比

```text
服务量变化占比
=（该维度项本期服务量 − 该维度项对比期服务量）÷ 本期整体服务量 × 100%
```

该指标用于描述某个维度项的服务量变化规模，不直接等同于其对整体万服变化的贡献。

### 4.3 万服波动贡献

```text
万服波动贡献（次/万单）
= 该维度项本期服务量 ÷ 本期整体订单量 × 10000
− 该维度项对比期服务量 ÷ 对比期整体订单量 × 10000
```

该指标用于解释某个维度项推高或压低整体万服的绝对贡献。正值表示推高，负值表示压低。

报告主要按照万服波动贡献排序，服务量变化占比作为辅助解释。每个拆解维度内部的维度值可以汇总解释整体万服变化，但城市、事件、FAQ、品类、渠道和战区等不同拆解口径存在重复归因关系，不得跨维度简单加总。

## 五、文件修订策略

### 5.1 需求与调研文件

- 将“完全模拟项目”改为“真实实习项目复盘”。
- 虚构 Persona、访谈人数和比例保留时标为复盘研究模型或示例样本。
- 将邮件相关痛点和方案改为大象机器人个人/群聊分发。
- 将数据准确性评测、权限隔离、标准化和快速部署明确为当前痛点。

### 5.2 产品设计文件

- 统一 7 维度、5 模块、能力链路和模块职责。
- 将未经证实的效率与覆盖数据标为复盘测算或目标值。
- 区分真实已验证功能与复盘补充设计。
- 原型生成提示词和可交互原型同步更新报告结构、维度名称和大象分发。

### 5.3 技术交付文件

- 评测体系保留为复盘设计，不写成真实完成的评测结果。
- 验收状态统一为“待验证”或“目标”，除非有真实证据证明通过。
- 统一服务量变化占比和万服波动贡献的名称、公式与展示字段。

### 5.4 上线运营文件

- 将 87.3%、4.2、用户量、成本等标为示例值或目标值。
- 删除模拟结果对应的“已通过”结论。
- 消息通知渠道统一为大象机器人。
- 将权限、评测、标准化和部署纳入后续建设与监控规划。

## 六、验收标准

完成修改后必须满足：

- 15 个文件中不再把整个项目声明为完全模拟项目。
- 所有无法证实的数字均邻近标注“复盘测算”“目标值”或“示例值”。
- 全部分析维度统一为指定的 7 个维度，不出现六类 WBR 分析视角。
- 报告信息架构统一为 5 个内容模块。
- 全链路分发统一为大象个人/群聊分发，不将邮件描述为真实主链路。
- `anomaly_calc` 与 `experience-anomaly-report` 的职责在各文件一致。
- 评测、权限隔离、工程标准化和快速部署均表述为当前痛点或待建设能力。
- 服务量变化占比和万服波动贡献不再混用。
- `选题推荐报告.md` 以 UTF-8 正常读取，不存在实际文件乱码。
- 可交互原型中的页面文案、维度标签和计算字段与文档口径一致。
